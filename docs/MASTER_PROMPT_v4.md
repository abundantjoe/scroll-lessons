## 5. The validated 9 µm pipeline (rebuild exactly; each script is 100–200 lines)
5.1 Model call (fixed): `python -m vesuvius.ink_detection.inference.infer <stack.zarr> <ckpt.pth> <out_forward.tif> --direction both --tta-mirror --batch-size 4 --gpus 0 --no-compile --num-workers 3`. Input: surface-volume OME-zarr (group with array "0", axes z y x, uint8, >= 17 slices; villa centres a 17-of-21 window; use 28-slice stacks), robust_mad 1–99 % normalisation inside villa, patch 128, stride 64, Hann blend. Output uint8 TIFF = probability × 255; `--direction both` also writes `<out>_reverse.tif` (the same stack with the slice order flipped). The model is NOT depth-order invariant; on the team's renders `--flip-normals` gives the trained orientation; on own patches the orientation is unknown and both orders are always read. `--tta-mirror` (average of mirror variants) was promoted on 2026-09-12: w028 reference AUC 0.784 -> 0.823, w040 regression 0.990, rule levels unchanged; ~2.5× a plain pass.
5.2 Gate A (must pass before any target read; bar written first in RULES.md): w040 native stack (level 0 synced from the bucket) through 5.1, scored pixel-wise (ROC AUC) against `w040_inklabels.zarr` level 0 slice 14 (> 128 = ink) on pixels where `w040_supervision_mask.zarr` slice 14 > 0. Bar: forward AUC >= 0.98, reverse < 0.70. Reference: 0.9966 / 0.4963 on 1,629,734 supervised px; forward mean on ink 0.758, on blank 0.252. If it does not reproduce within 0.01, stop and diagnose (slice count, order, dtype, zarr level); read no target until it does.
5.3 Gate B (renderer): `vc_render_tifxyz --volume <local cache dir> --remote-url s3://vesuvius-challenge-open-data/PHerc0139/volumes/20250728140407-9.362um-1.2m-113keV-masked.zarr/ --segmentation <w040 tifxyz dir> --zarr-output <out.zarr> --scale 1 --group-idx 0 --num-slices 28 --slice-step 1 --cache-gb 8 --voxel-size 9.362 --voxel-unit micrometer --flip-normals --crop-x 1152 --crop-y 2048 --crop-width 2048 --crop-height 2048`. Reference: byte-identical to the team stack on that crop (Pearson 1.000 on all 28 slices); through 5.1 the crop scores 0.99681 vs 0.99681 on the team stack. This crop is the standing regression: after ANY change to sampling or model input, forward AUC >= 0.987 and reverse < 0.60, else revert.
5.4 Gate C (w028, the calibration): `python -m vesuvius.ink_detection.preprocessing.prepare_9um_isotropic_input https://vesuvius-challenge-open-data.s3.us-east-1.amazonaws.com/PHerc1667/segments/20251208130119-w028_20251208130119156_flatboi/surface-volumes/2.399um-0.22m-78keV-volume-20251217075048.zarr <out.zarr> --level 2 --workers 16` (mean-pools 4 planes -> 21 slices at ~9.596 µm, ~3 min; if the final rename fails, rename `<out>.zarr.partial` yourself), then 5.1. Reference on the aligned labels (slice 10, > 0 = ink, supervision mask > 0): forward AUC 0.9998, reverse 0.531; forward mean on ink 0.772, blank 0.235. LEAK: the model draws the 4 labelled letters crisply and every other letter on the sheet as blobby rows; w028 and w040 are in its training corpus, so label AUC measures memorisation. Therefore every calibration uses UNLABELLED text: reference = the team's 2.4 µm w028 prediction block-averaged 4×4 onto the pooled canvas and divided by 255; text = reference >= 0.40, blank = reference <= 0.25, on-sheet only (CT > 0), pixels within 60 px of any labelled letter excluded. The JUDGE for any w028 map = pixel ROC AUC on those two classes: seed42 forward 0.784 (0.823 with TTA), reverse 0.49. Any model or input variant is promoted only if it raises this by >= 0.01 AND passes 5.3.
5.5 Frozen candidate rule (SCREEN-POWER, never retuned): unit = square of side round(sqrt(0.5)×10000/µm) px (0.5 cm²; 737 px at 9.596 µm, 819 at 8.64, 755 at 9.362); a unit is valid if >= 90 % of its pixels are on-sheet; flagged when forward mean >= 0.36 AND forward − reverse >= 0.08. Levels on w028 unlabelled text: forward 0.40, margin +0.12; blank papyrus 0.29, 0.00. Power: 1 cm² windows 9/9 text vs 0/11 blank flagged; 0.5 cm² 22/24 vs 0/35. PROMISING CANDIDATE = >= 3 adjacent (4-connected) flagged units on one chart AND marks in rows at 2–4 mm letter height. BLANK = no flagged unit over >= 1.5 cm² of valid units. Whole-map mean is NOT a verdict (text-bearing w028 averages 0.34; blank charts 0.30–0.43). Report also 1 cm² units.
5.6 Seeds: read level 3 of the surface-prediction zarr over https (zarr v2 array at `<pred>.zarr/3`, shape z y x = level-0/8); threshold >= 128; take 5 slices spread over the z-band; per slice split predicted voxels by distance from the slice centroid into outer/middle/inner thirds and pick well-separated voxels (>= 40 level-3 voxels apart); output level-0 coordinates (x, y, z) = (col×8, row×8, slice×8); ~30 seeds per z-band. z-bands per scroll: three, spread over the scroll's z extent (e.g. for PHerc0175A, z extent 12748: 3000–4000, 5800–6800, 9000–10000). The tracer takes each seed as `--seed X Y Z` in level-0 CT voxels.
5.7 Tracer (normal grids MANDATORY): params JSON `{"mode":"seed","min_area_cm":0.2,"generations":60,"thread_limit":2,"cache_root":"<per-scroll cache dir>","direction_fields":[],"voxelsize":<pitch µm>,"normal_grid_path":"<dir>"}` where `<dir>` contains the store's `metadata.json` (curl it from `.../<vol>-surface-...-m7-L0-th0.2.normal-grids/metadata.json`) and a file `normal-grids-remote.json` containing `{"url": "https://vesuvius-challenge-open-data.s3.us-east-1.amazonaws.com/<scroll>/representations/predictions/surfaces/<vol>-surface-20260413222639-surface-m7-L0-th0.2.normal-grids"}` (grid files are then fetched lazily into that dir). Run `vc_grow_seg_from_seed --volume s3://vesuvius-challenge-open-data/<scroll>/representations/predictions/surfaces/<vol>-surface-20260413222639-surface-m7-L0-th0.2.zarr/ --target-dir <patches dir> --params params.json --seed X Y Z`; one process per core; output `auto_grown_<timestamp>/{x,y,z}.tif + meta.json` (float32 grids of level-0 voxel coordinates, one cell per 20 voxels, ~4 cm² after 60 generations; 30–90 min per patch, faster once the grid cache is warm). Without normal grids the tracer is 100× faster and grows surfaces that cut across windings: void.
5.8 Patch QC (before any render): from the tifxyz grids compute per-cell normals (cross product of the u and v differences); PASS if mean |n_z| <= 0.50 AND fraction(|n_z| > 0.7) <= 0.25 AND area >= 0.5 cm² (the scroll axis is z; a winding's normals lie in the xy plane). Reference: w040 mesh 0.25 / 0.06 PASS; patches grown without grids 0.75–0.83 FAIL. Then the CT-mask check: sample 100 patch points in the CT at level 4 (coordinates ÷ 16, axes z y x); if > 50 % are zero the patch lies outside the masked CT: UNREADABLE, never rendered (about 10 % of patches). Confirm the geometry on at least one chart per scroll by overlaying the patch points on a level-4 CT slice (a valid sheet crosses a slice as a thin curve, not a wide band).
5.9 Render: `vc_render_tifxyz --volume <cache dir> --remote-url s3://vesuvius-challenge-open-data/<scroll>/volumes/<vol>-<pitch>um-1.2m-<keV>keV-masked.zarr/ --segmentation <patch dir> --zarr-output <render.zarr> --scale 1 --group-idx 0 --num-slices 28 --slice-step 1 --cache-gb 8 --voxel-size <pitch> --voxel-unit micrometer --auto-crop` (~1 min per 4 cm²; output group "0" = 28×H×W uint8). An all-zero render is a transient fetch failure: delete and re-render, give up after three.
5.10 Read: assert >= 0.5 cm² on sheet (CT mid slice > 0) and on-sheet intensity std > 5; record the per-slice mean profile and the crest slice; run 5.1; compute on-sheet forward/reverse means, fractions > 0.5 and > 0.75, connected regions > 0.5 mm² at forward > 0.5 and the largest, forward − reverse, the unit rule 5.5 at 0.5 and 1 cm² (counts, largest cluster, brightest flagged unit), the verdict; write a contact sheet (CT mid slice | forward as stored | reverse as stored | forward − reverse per unit with flagged units circled; 1 cm bar on every panel) and the ledger line. Also flag "bright ink visible in the render itself" (page item 7): report the fraction of on-sheet pixels in the CT mid slice above the 99.5th percentile that form elongated marks 2–4 mm long; list any chart where that exceeds 1 % for a human look.
5.11 Automation: one script processes a patch directory: QC -> mask check -> render -> read, idempotent from markers, skipping ledgered keys; run one such loop per GPU over all patch directories; tracers run on the CPU cores meanwhile. Log throughput daily in LEDGER.md: cm² read, charts, scrolls to first verdict, MB/s, GPU idle fraction.
5.12 Review folder for the team: `review_sheets/eligible/` (charts on eligible scrolls) and `review_sheets/ineligible/` (controls), named `<scroll>__<segment>__<verdict>.png`, an INDEX.md with the numbers per sheet, and `eligible/overlays/`: CT with purple where forward > 0.5 and forward − reverse > 0.10, a full-resolution forward − reverse panel, and the forward map as stored. Overlays are derived views for eyes only. Refresh on a timer.
5.13 Flattening for submission (required by rule 1): the tracer's tifxyz is a 3D grid without a distortion-minimising parametrisation. Before packaging, flatten the candidate mesh with `vc_flatten` (ABF++; `vc_render_tifxyz --flatten` also exists) or `flatboi` (SLIM) from the Linux VC3D image, render the flattened mesh with 5.9 at 28 slices, re-read it with 5.1 (both orders), and use THAT render and mesh for the package; the letters must still be there. Name the image after the flattened mesh.
5.14 Packager + verifier (dry-run on w040 on day 0; the dry run must pass every file-derived check and fail exactly "not eligible" and "fewer than 10 letters"): inputs = read directory, flattened mesh, window x, y with side = round(20000/µm) px (4.00 cm²), volume id, µm/px, letter list, held-out demonstration text, method text. Outputs = forward_window.tif/png and reverse_window.tif/png (unaltered crops with a 1 cm bar; the png named after the mesh), ct_window.png (fibre-visible render), rows.png (the forward window with a horizontal baseline drawn through each text row OUTSIDE the letters, as the page allows), the mesh copy with SHA-256 hashes, package.json (scroll, volume id, µm/px, window px/mm/cm², bar px, checkpoint and exact call, letters with x, y, height and width in px and mm and the reading, both orders present, held-out demonstration, method, Docker image reference), method.md, and the held-out validation numbers (Gate A/C results and the w028 judge). The verifier re-derives every number from the files: area 4.00 ± 1 %, bar = 10000/µm ± 1 px, forward window byte-identical to the source TIFF, both orders present, mesh present and hashed and flattened, >= 10 letters inside the window with sizes, held-out text and method present, scroll on the eligible list, image named after the mesh.

- The 9 µm model is a public checkpoint whose training corpus (aligned21_hybrid_3d2d.json in villa) is PHerc0139, PHerc1667, PHercParis4 and PHerc0814 renders: none of the 23 eligible scrolls, so training and prediction regions cannot overlap; state this with the checkpoint name and link. - Held-out validation (rule 5): include the Gate A/C numbers and sheets (w040 native, w028 pooled) and, for the 2.4 µm route, the w028 2.4 µm calibration run.
- Reverse-order control: for the submission window show the forward and reverse maps side by side; real ink appears in one order and much weaker in the other; give the per-unit numbers.
- Held-out region with different plausible letters: read a second, non-overlapping window of the same scroll (a different patch, at least 2 cm away or another winding) with identical settings; it must show different, plausible letters or plausible blank papyrus, never copies of the first window's shapes. Include it.
- Scale: letters 2–4 mm tall, in rows parallel to the horizontal fibres, with row pitch consistent across the window; report the pitch.
- Never fine-tune on the submission region. If a model is ever trained on a candidate scroll (only after a verified first window exists), labels come from one half of the surface and the demonstration window is on the other half, and this is documented.
- Model window size: state the receptive field (128 px patches, 17 slices) and that no window larger than a letter row was used.

## 9. SUBMISSION PROTOCOL (when to submit, per scroll)
1. Trigger: a chart with a PROMISING CANDIDATE by 5.5 (>= 3 adjacent flagged 0.5 cm² units). Within the hour: read the adjacent patches around it (grow or trace neighbours) so the region reaches a hole-free 4 cm²; run both orders on every added patch.
2. First reading by the session: on the unaltered forward map, list every letter-like mark with position, height and width (px and mm) and the proposed Greek letter; count only marks 2–4 mm tall sitting in rows. If fewer than 10 fall inside any 4.00 cm² window, the scroll is NOT submittable yet: keep extending the region and re-read; never lower the count or resample the map.
3. Choose the 4.00 cm² window (side = round(20000/µm) px) that contains the most listed letters; never enhance, threshold, sharpen or redraw the map to make them clearer.
4. Flatten the mesh (5.13), re-render and re-read; the letters must persist in the flattened render (if they do not, the candidate is NOT ESTABLISHED).
5. Package (5.14) and run the verifier; it must print all checks PASS.
6. Send the owner: "$50,000 SUBMISSION READY: PHerc XXXX — package at <path>, verifier OK, N letters in window", with forward_window.png, reverse_window.png, ct_window.png, rows.png, the held-out window images and the letter list. The owner's team verifies the letters independently. Only after they confirm >= 10 legible letters is the form submitted (the same day), with the package link (private, downloadable) and the volume id. One submission per scroll; do not resubmit the same scroll unless the organisers ask.
7. After a submission: copy the recipe (scroll, route, depth, seeds, settings) into METHOD.md, rerun it on every remaining scroll before anything else, and keep the discovery private until the organisers announce.
8. Stop conditions (do NOT submit): fewer than 10 letters inside one 4.00 cm² window; letters visible only after any alteration; the reverse order showing the same marks at the same strength; marks coinciding with tears, hole rims or fibre bands in the CT; the flattened render losing the letters; the team not confirming legibility.
