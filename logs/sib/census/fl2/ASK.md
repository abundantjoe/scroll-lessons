# census FL2 (PHerc1203, second worker, lane 1): notes and questions (defaults applied)

1. Organizer segment list. The template's `fl.py list` (54b29c96) returns 138 tifxyz dirs for PHerc1203, not 22. 116 of them are `segments/raw/<segment>/versions/<n>` edit-history snapshots of the same sheets. The pipeline keeps only the 22 top-level `segments/raw/<segment>` dirs, excludes the 5 T0 tracer test ids (as the primary did on 2026-09-30), and ranks the remaining 17 by x.tif size. Lane 1 takes the odd ranks: 8 segments (logs/sib/census/fl2/organizer_selection.json).
   Default: this filter. The even/odd split only lines up if the primary (fl-pherc1203) applies the same snapshot filter and T0 exclusion. If it uses the template's raw 138-entry list, the two lanes overlap or miss segments; please check its selection file.
2. Seeds. The template's `fl.py seeds` has a fixed 8-entry z/azimuth plan, so `... 48` yields at most 8 candidate seeds, and lane 1 gets at most 4 auto-grow attempts, not 40. Default: the template unchanged (brief: logic unchanged, parameters only). Reported here, not worked around.
3. Organizer segments are rendered without a self-intersection gate (template behaviour; the brief's 0-self-intersection gate is for auto-grow). The fl-pherc1203 NOTES report that its 3 largest raw segments are not clean. Each segment's vc_tifxyz_selfcross report is saved beside its tiles (<SEG>/selfcross.json), so any candidate tile can be checked against crossing sites before a read counts.

4. Seed-list extension (orchestrator 06:00Z, step 2). `fl.py seeds` (54b29c96) is deterministic: a fixed 8-entry z/azimuth plan on the CT-mask centroid axis. A "new round" with the same command returns the same 8 seeds, so extending NSEEDS would regrow the same papyrus and duplicate tiles; it adds no material. Default: no extension with identical seeds; the lane finishes its 4 seeds (s1, s3, s5, s7) and stops (PIPELINE_DONE). To extend usefully, the seed plan would need new z fractions/azimuths, which is a code change: it needs your declaration.
5. Incident (2026-10-01 ~06:09-07:38Z): two pipeline instances ran at once and auto-grow segments s1, s5 and s7 were grown twice into the same directory. Those records were removed and regrown. Organizer tiles (8 segments) and s3 were not affected.
