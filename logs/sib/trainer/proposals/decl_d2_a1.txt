Written 2026-09-25 by the sibling trainer session (builder only). Every number below comes from logs/sib/trainer/throughput.json and
logs/sib/trainer/report.json (synthetic data, 4 vCPU Intel Xeon with AMX, 15 GB RAM). No real data was trained on, and no image was opened.

0. Why an amendment is needed
   D0-HW dates D2 at "6 days after a GPU is provisioned; NOT RUN if none by 2026-11-15". No GPU exists. CPU sibling sessions do exist now
   (logs/sib/registry.json). DECL-D2 (arms, bars, folds, J decisions 2 of 3) is unchanged by this proposal. It only proposes how the arms
   run on CPU sessions and a D2 date that CPU sessions can meet. If nothing is declared, the default stands: D2 NOT RUN at 2026-11-15,
   which counts as not-passed for K1.

1. Trainer (frozen before launch; hashes are recorded at freeze time, not now)
   tools/sib/trainer/d2_train.py, d2_data.py and ckpt_shards.py (sha256 in logs/sib/trainer/report.json).
   - Model, loss and optimizer: official villa 41701aa components, started from base ink_9um hybrid_3d2d seed42 step-075000
     (sha256 e635558a...9cab) only.
   - Bitwise equivalence to tools/d3/d3_train.py: with tile 128, no rotation and the D3 layout, the per-step losses and final
     weights of CTRL, FA, NULLA and REVA are bitwise identical to D3's on the same synthetic pools
     (tests/sib_trainer_integration_test.py::test_d3_equivalence).
   - Determinism: same config and data give identical loss curves and weights (fp32, 1 thread; P128, NULL with micro-batching,
     REV with stitched forward).
   - Resume: a resume from local state, or from the remote git shards alone after the run dir is deleted, is bitwise identical to an
     uninterrupted run.
   - Paired sampling: P384, NULL and REV with the same seed draw an identical (patch, z offset, rotation) sequence (sample_digest).

2. Arms (DECL-D2 unchanged: K6 = 4 candidate arms + base reference; 3 seeds each; seed 1 read, seeds 2-3 give variance on pixel metrics)
   Common config (make-config flags):
     --batch 32 --steps 12000 --rot24 --subtile --threads 4 --z-jitter 2 --z-centre-offset 0 --lr 2e-5 --weight-decay 3e-5
     --log-every 50 --ckpt-every 250 --remote-ref refs/heads/<session branch>-ckpt --hash-sources
     sources, pooled (no per-batch quotas), all role train:
       pairs0139 = tilegrid3:<pairs0139 output dir>   (complete grid-aligned 3 x 3 blocks of kept 128 px tiles = exact 384 px
                   render crops; ASK 3; not published at the time of writing)
       pairs0814 = stagec:logs/sib/pairs0814  (+ --allow-ids pairs0814=<declared filter>, see 4c)
       (+ 0332 / 0500P2 only if their protocol check passes and they are declared)
   P128 : --arm P128 --micro-batch 32                                    (tile 128)
   P384 : --arm P384 --micro-batch 4 [fp32] / 8 [bf16]  --forward F384 (stitched: --micro-batch 8 in both precisions)   (tile 384)
   NULL : --arm NULL (= P384 + one fixed label derangement over all pooled train patches, no fixed point)
   REV  : --arm REV  (= P384 + every 21-slice input stack reversed in depth, labels unchanged)
   Seeds: --seed 1, 2, 3 (literal). Sampling, jitter, rotation and augmentation streams derive from the seed only, so arms that share
   a seed and a tile are paired.
   Base reference arm: the base checkpoint itself; it needs no training.

4. Decisions the orchestrator must make before freezing (the trainer implements every option)
   a. F384, the forward mode for the P384, NULL and REV arms. Both modes train, but they mean different things:
      - "full": the model sees the whole 384 px tile. The base architecture is fully convolutional and accepts 384 x 384 unchanged.
        This is the only mode that gives the "letter-scale context" of the DECL-D2 hypothesis. However, the official infer rebuilds
        the model from the checkpoint config and tiles at 128 px. Building from patch_size 384 is not possible: it changes the
        architecture (measured: parameter shapes differ). A full-mode model therefore needs a 384 px tile inference path. That path
        is not official, so it needs its own gate before any D2 map: on the base model, 384-tile inference vs official 128-tile
        inference on a control window, with a declared tolerance.
      - "stitched": the official trainer's stitch_factor 3 semantics. The model sees nine independent 128 px crops, and the loss is
        taken over the 384 px tile. Official 128 px inference applies unchanged. P384 then tests loss- and normalisation-scale
        context, not receptive-field context.
      Recommendation (for the orchestrator to judge): declare "full" together with a 384 px inference gate, since it is the arm that
      tests the hypothesis. Also report the "stitched" number as the cost bound.
   b. Optimiser recipe. The default is the section 4.D2 archive fine-tune recipe that D3 used (AdamW 2e-5 constant, weight decay 3e-5,
      clip 1.0). DECL-D2 says "base recipe", and the base itself was trained with SGD lr 0.01, cosine schedule, 1000 warm-up steps and
      batch 64. The amendment must pin one. Only AdamW with a constant rate is implemented and tested.
   c. Data filters. Examples: exclude base-training papyrus (pairs0814 annotates the same-papyrus fraction with the 46527 re-trace)
      and duplicate groups. Declare them as patch_id allowlists with a pinned sha256 (--allow-ids).
   d. Stored patch context. pairs0814 stores 384 px patches (xyz only inside the patch, every 24 px). With 24 x 15 deg rotations:
      - P384 on a 384 px patch loses a mean 11.4 % of pixels to ignore (17.2 % at 45 deg);
      - P128 with --subtile loses 3.8 %;
      - P512 cannot run on 384 px patches at all.
      Remedy, if declared: the pairs sessions re-render with an 81 px margin (546 px stored) so that every arm gets corner-free
      rotations. Otherwise the asymmetry is declared and reported as it is.
   e. FL-09 reading (CORR-RETRACE-RULE applies: tools/sib/trainer/contam_check.py uses point-to-triangulated-surface
      clearance and the fail-closed vertex-OR-surface same-papyrus rule). "128 vox plus a 64 px halo" can mean (i) the patch dilated by 64 px on its canvas, then >= 128 vox in 3-D, or
      (ii) >= 192 vox. pairs0814 xyz has no halo, so reading (i) needs the halo added by the checker; (ii) is conservative. Declare one.
   f. bf16. Use it only if the orchestrator's AMX gate passes. The config then carries the gate record (path + sha256, pass: true);
      the trainer refuses bf16 training otherwise. bf16 arms are not bitwise comparable with fp32 arms, so all arms use the same precision.

5. Reclaim safety and repo growth (measured 2026-09-25 on refs/heads/claude/gifted-bell-gavnl5-sib-trainer-ckpt)
   - A local resume state (weights + AdamW moments + all RNG and stream states) is saved every 250 steps: 414,963,964 bytes.
   - The same state is force-pushed as one parentless commit of 5 shards (max 90,000,000 bytes, 414,952,758 bytes in total).
     Save + push + local prune took 90.3 s.
   - At completion, the final weights (138,362,143 bytes, 2 shards) replace it on the ref.
   - A fresh bare fetch returned the final weights byte-identical (sha256 4e3572c7...), and the ref holds exactly 1 commit.
   - Tests show that a resume from the shards alone is bitwise identical to an uninterrupted run.
   - Repo growth: superseded states stay on GitHub as unreachable objects until its own garbage collection.
     Pushing every 24 h gives about 14 pushes per P384 fp32 session (9 bf16) and 2 per P128 session.
     Over 12 sessions that is about 55 GB at fp32 (35 GB at bf16), far above GitHub's ~5 GB guidance (DECL-OFFLOAD-1).
   - Proposal: every 72 h (about 18 GB at fp32, 12 GB at bf16), or remote pushes only when a check-in finds the session at risk.
     The owner decides (ASK 6).
